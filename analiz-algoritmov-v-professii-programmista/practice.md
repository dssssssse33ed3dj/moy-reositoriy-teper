## 01. Минимальное число

Ограничение по времени: 2 секунды · 
Ограничение по памяти: 256 МБ 
Задача - Верните минимальное число из непустого списка целых чисел.

 Входные данные: Список numbers из n целых чисел. 
Выходные данные: Одно целое число - минимум. Пример [8, 3, 11, -2, 5] → -2 

Данные для замеров 
• 1000 случайных чисел
• 100 000 случайных чисел 
• 100 000 чисел, минимум в конце

 Сценарий 1. Большой вход, память ограничена n = 10 000 000. Дополнительная память не более 8 МБ. - подходит
Оба варианта имеют сложность O(n) и дополнительную память O(1) - они не создают копий списка. Сортировки (4 и 5) нам не подходят: для 10 млн элементов sorted() съест более 100 МБ памяти, а .sort() - более 40 МБ (на 100к элементов .sort() уже занял 390 КБ, на 10 млн это будет ~39 МБ), что превышает лимит в 8 МБ. Циклы for и while тоже подходят по памяти, но min() работает в разы быстрее, так как написан на C.

 Сценарий 2. Малый вход, нужен быстрый ответ n = 100. Ответ нужен для одного запроса как можно быстрее – тоже подходит
На малых данных (100 элементов) на первое место выходит скорость самого вызова функции и отсутствие накладных расходов Python-цикла. heapq (0.038 мс) и min() (0.041 мс) работают практически мгновенно, так как написаны на C. Использование while или reduce (около 0.5 мс) работает медленнее в 10 раз из-за интерпретации байткода, а пузырьковая сортировка вообще неэффективна.

Выходные данные
True или False.
Пример
[4, 9, 2, 9] → True
Данные для замеров
1000 случайных чисел
100 000 разных чисел

Входные данные
Два списка целых чисел left и right.
Выходные данные
Список общих чисел. Порядок не важен.
Пример
[1, 2, 2, 4], [2, 2, 3] → [2]
Данные для замеров
два списка по 1000 чисел
два списка по 100 000 чисел
два отсортированных списка по 100 000 чисел
Сценарий 1. Большой вход, память ограничена
В каждом списке 1 000 000 чисел. Свободной памяти мало.

В каждом списке 100 чисел. Ответ нужен быстро.
Сценарий 1 (По 1 000 000, памяти мало): Подходит — .sort() + два указателя. Сортируем оба списка на месте (O(1) доп. памяти) и ищем совпадения. Множества (set) съедят слишком много памяти.
Сценарий 2 (По 100, быстро): Подходит — set & set. Твой замер показал 0.225 мс. Пересечение множеств работает на уровне C.

В ids лежат все числа от 0 до n, кроме одного. Верните пропущенное число.
Входные данные
Список ids и число n.
Выходные данные
Одно целое число.
Пример
ids = [3, 0, 1], n = 3 → 2
Данные для замеров
n = 1000, список перемешан
n = 100 000, список перемешан
n = 100 000, пропуск в начале

Сценарий 1 (n=10 000 000, память ≤ 8 МБ): Подходит — Математика (Сумма прогрессии). Твой замер показал 2.016 мс и 0.1 КБ памяти. Идеально: O(1) памяти, один проход. XOR тоже подходит, но работает дольше (190 мс).
Сценарий 2 (n=100, быстро, исходный список сохраняется): Подходит — Математика. Работает за один проход, ничего не копирует и не сортирует. sum() написан на C, поэтому это доли микросекунды (0.030 мс).
