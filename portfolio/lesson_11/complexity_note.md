# Заметка о сложности · занятие 11

Для каждой функции своими словами: что считается заранее, что хранится между итерациями,
как записан запрос или индекс и какая из этого формула, время и дополнительная память.

## highest_altitude

- Что хранится между итерациями: текущая накопленная высота `current_alt` и максимальная найденная высота `max_alt`.
- Почему ответ не меньше 0: по условию маршрут всегда начинается в точке 0, поэтому начальная высота уже равна нулю.
- Время: O(n) — один проход по списку изменений высот.
- Память: O(1) — фиксированное число переменных для подсчета высоты.

## range_sums

- Перебор и его сложность: вырезать срез `nums[l:r]` и суммировать заново на каждый запрос; сложность O(q * n).
- Что лежит в prefix[i] и почему ячеек n + 1: сумма первых `i` элементов массива; `n + 1` ячеек нужно, чтобы удобно хранить базу `prefix[0] = 0` для пустых префиксов.
- Формула ответа на запрос (l, r) и почему без поправок на единицу: `prefix[r] - prefix[l]`. Поправок нет, так как запрос задан полуинтервалом, и правая граница `r` совпадает со смещением в массиве префиксов.
- Какие запросы считаются неверными и почему Python сам их не остановит: запросы вне границ `0 <= l <= r <= len(nums)`. обычные срезы при неверных индексах просто вернут пустой список вместо ошибки.
- Время: O(n + q) — O(n) на подготовку массива префиксов и O(1) на каждый из q запросов.
- Память: O(n) — для хранения массива префиксных сумм длины n + 1.

## pivot_index

- Перебор и его сложность: для каждого индекса `i` запускать два суммирования `sum(nums[:i])` и `sum(nums[i+1:])`; сложность O(n²).
- Что хранится в left и откуда берётся right: в `left_sum` хранится сумма всех элементов строго слева от `i`; правая сумма вычисляется на лету как `total_sum - left_sum - num`.
- Почему left увеличивается после сравнения: текущий элемент `num` не должен входить в левую сумму при проверке баланса для индекса `i`, он добавляется туда только при переходе к следующему шагу.
- Время: O(n) — один проход для `sum(nums)` и один проход циклом по массиву.
- Память: O(1) — только пара переменных для хранения сумм.

## count_vowel_ranges (домашнее задание)

- Чем формула ответа отличается от range_sums и почему: Формула range_sums для полуинтервалов `[l, r)` выглядит как `prefix[r] - prefix[l]`. В этой задаче правый конец `r` задан **включительно**, поэтому формула меняется на `prefix[r + 1] - prefix[l]`. Мы смещаемся на `r + 1`, чтобы префиксная сумма полностью захватила и учла элемент на позиции `r`. При этом префикс хранит не сумму чисел, а накопленное количество валидных слов.

## Ошибки из bugs_11.py

- longest_zero_sum → Вход `nums=[1, -1]`. Из-за отсутствия базы `{0: -1}` в словаре `first`, алгоритм не мог учесть отрезки с суммой 0, начинающиеся с самого первого элемента массива. Нарушено базовое состояние префиксов.
- last_pivot_index → Вход `nums=[2, 0, 0]`. Из-за шага цикла `range(len(nums) - 1, 0, -1)` проверка останавливалась перед индексом 0, из-за чего функция не могла найти баланс на самом первом элементе. Нарушены границы обхода массива.
- max_query_sum → Вход `nums=[-5, -1, -3]`, запрос `[(1, 2)]`. Переменная `best` была инициализирована нулем, поэтому на массивах с исключительно отрицательными суммами запросов функция выдавала неверный ответ 0. Нарушена инициализация нейтральным элементом для поиска максимума.
