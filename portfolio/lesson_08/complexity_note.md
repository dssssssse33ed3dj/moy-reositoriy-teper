# Заметка о сложности · занятие 8

Для каждой функции своими словами: что хранится между итерациями (инвариант),
время и дополнительная память, почему именно так.
## pair_sum_brute

- Время: O(n^2) - два вложенных цикла перебирают все возможные пары.
- Память: O(1) - новые структуры данных не создаются.

## pair_sum

- Инвариант: искомая пара (если есть) находится внутри границ [left, right].
- Время: O(n) - на каждом шаге один из указателей сдвигается к центру.
- Память: O(1) - используются только два числовых указателя.
- Почему указатели не пропускают пару: массив отсортирован. Если сумма мала - двигаем left вправо для увеличения, если велика - двигаем right влево для уменьшения. 

## dedup_sorted

- Инвариант: до индекса write_index элементы уникальны и отсортированы.
- Время: O(n) - один линейный проход по списку.
- Память: O(1) - перезапись элементов происходит на месте.

## compress

- Инвариант: до write_index записана сжатая строка, read_index ищет новую серию.
- Почему запись не обгоняет чтение: длина сжатой серии - символ + цифры длины, всегда меньше или = длине исходной серии одинаковых символов
- Время: O(n) - каждый символ считывается ровно один раз.
- Память: O(1) - изменение и отсекание хвоста происходят на месте.

## move_zeros

- Инвариант: левее write_index нет нулей, а между write_index и read_index - только нули.
- Время: O(n) - один проход указателя чтения по массиву.
- Память: O(1) - ненулевые элементы меняются местами с нулями (in-place).

## Ошибки из bugs_08.py

- count_cheap_pairs → вход `prices=, limit=4`. Вместо `<` стояло `<=`, из-за чего пары с суммой равной лимиту ошибочно считались дешевле.
- dedup_keep_two → вход `ids=`. Короткие списки ломались из-за безусловного удаления `del ids[2:]`, приводившего к неверной длине 2.
- is_mirror → вход `["a", "b"]`. Из-за условия `while i < j - 1` цикл завершался до проверки смежных элементов, возвращая True для разных символов.
