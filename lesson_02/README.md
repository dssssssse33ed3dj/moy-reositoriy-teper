# Занятие 3 · Временная сложность и O-нотация

Вторая папка курса. Занятие 2 идёт без домашней работы, поэтому нумерация
папок и нумерация занятий здесь расходятся: папка вторая, занятие третье.

**Разобрали:** что считать за операцию, T(n) и S(n), определение O через
c и n₀, шесть классов роста, анализ кода, скрытая стоимость строк,
худший и средний случай, память, ограничения из условия задачи.

**Домашнее задание** — три файла в этой папке. Сдать до начала занятия 4:
с проверки ваших оценок замером оно и начнётся.

## Что лежит в папке

| Файл | Что это | Трогать |
|---|---|---|
| `fragments.py` | двенадцать рабочих функций, которые нужно разметить | нет, только читать |
| `answers.py` | **бланк задания 1**: три словаря под ваши ответы | заполнять |
| `test_lesson_03.py` | автопроверка задания 1 | нет |
| `limits.md` | **бланк задания 2**: шесть условий и седьмой пункт | заполнять |
| `acceptance.md` | **бланк задания 3**: приёмка по четырём пунктам | заполнять |

Три бланка — по одному на задание. У задания 1 бланк не в Markdown, а в
Python: ответы читает `pytest`, поэтому они лежат словарями прямо в
`answers.py`. Отдельный `.md` для него не нужен — в третьем словаре
`WORST_CASE` пишется тот же текст, что писали бы в заметке.

Структуру бланков не меняйте: по ней я проверяю.

## Что сдаётся

Автопроверку запускайте из папки задания:

## Чек-лист перед Pull Request

Что должно лежать в папке:

- [ ] `answers.py` — заполнены все три словаря: `TIME`, `SPACE`, `WORST_CASE`;
- [ ] `limits.md` — шесть условий и седьмой пункт про ошибку модели;
- [ ] `acceptance.md` — четыре пункта приёмки;
- [ ] `fragments.py` и `test_lesson_03.py` — без правок: тест сверяет отпечаток
      ответа, и подогнать его редактированием не выйдет.

Что проверяется:

- [ ] `pytest test_lesson_03.py -q` проходит целиком, ни одного FAILED;
- [ ] в записи оценок нет множителей и младших слагаемых: `O(n)`, а не `O(2n)`
      и не `O(n + 5)`;
- [ ] там, где на входе две независимые величины, в ответе обе: `O(n + m)`;
- [ ] у каждого из шести условий в `limits.md` есть **своя** строка «почему это
      верно», и в ней стоит число, а не слова «потому что быстрее»;
- [ ] седьмой пункт `limits.md` заполнен: либо ошибка модели и как вы её
      поймали, либо «ошибок нет» **вместе с расчётом по двум условиям**;
- [ ] в `acceptance.md` рядом с классом сказано, какие операции вы считали;
- [ ] в первой строке каждого файла — фамилия и группа;
- [ ] всё лежит в ветке `hw-02`, а не в `main`.

Что написать в описании Pull Request, текстом:

- [ ] какие два фрагмента оказались спорными и почему вы остановились на своём
      ответе;
- [ ] вывод `pytest` последней строкой (`26 passed`) — скопируйте из терминала.
